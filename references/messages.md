# 话术设计说明

真正在用的文案**不在这个文件里**，在 `config/profile.yaml` 的 `messages` 段
（由 `scripts/onboard.py` 读你的简历生成草稿，你再改）。

这里只讲设计约束和归类规则。

---

## 三条硬约束

1. **按岗位类别固定取用，不按岗位实时生成**
   让模型每次现写，质量会飘，还可能编出你没做过的项目。
   而且改文案要改代码，没法快速迭代。

2. **≤ `fit.max_message_len` 字（默认 80）**
   `onboard.py --check` 会校验，超了直接报错。
   80 字大概是一屏能读完、又能把一件事说清楚的长度；
   太短（15～40 字）只剩技术名词，看不出你到底做了什么。

3. **不写姓名、学历、公司名、薪资、链接，不堆 emoji**
   对方点开聊天第一眼看到的应该是「这人做过什么」，不是一段自我介绍。

---

## 语气：口语化，像自己说话

| 别这么写 | 这么写 |
| --- | --- |
| 熟悉RAG全链路 | 我之前做过保险条款的RAG问答，切片到检索都是自己写的 |
| 具备后端开发能力 | 我主要写Python后端，Docker部署也是自己弄的 |
| 精通Agent开发 | 我做过维保调度的Agent，工具编排和防编造都是自己加的 |

要点：

- **用「我」开头**，别省主语，省了像简历条目
- **动词落地**：「写过 / 跑过 / 自己加的 / 自己弄的」，比「熟悉 / 掌握 / 精通」可信
- **一句一个信息**，多用逗号短句，别写成一长串定语
- **可以带一点口语词**（「这块」「都是自己弄的」「线上跑过」），但不要网络梗

---

## 结尾：不要「可聊」

「可聊」显得轻浮，像在约人闲聊，也不给 HR 一个明确的动作。按岗位分两种收尾：

| 岗位类型 | 收尾方式 | 例子 |
| --- | --- | --- |
| 技术岗（rag / agent / llm / eng / data） | 反问一句 | `您这边Agent主要落在哪块业务？` |
| 通用岗（default，HR 居多） | 给一个动作 | `合适的话我把简历发您。` |

技术岗对面多是技术负责人，愿意聊细节，一句具体的问话比「可聊」更容易接上；
通用岗对面是 HR，每天看几十条，直接说「我把简历发您」省掉他一个决策。

---

## 归类规则

`messages.classify()` 拿 **岗位名 + JD 正文** 去匹配 `categories` 里的关键词，
岗位名命中权重 ×3，正文命中权重 ×1，取总分最高的类别；全不中走 `default`。

默认五类：

| 类别 | 典型触发词 | 话术该突出什么 |
| --- | --- | --- |
| `rag` | rag、检索增强、知识库、向量、faiss、召回、问答 | 切片 / 检索 / 拒答这类具体链路 |
| `agent` | agent、智能体、工作流、工具调用、mcp、react | 工具编排、参数校验、防编造 |
| `llm` | 大模型、llm、算法、nlp、微调、lora、transformer | 落地项目 + 对原理的掌握 |
| `eng` | 后端、python、fastapi、并发、docker、linux | 能独立扛的后端能力 |
| `data` | 数据开发、数仓、etl、hive、爬虫、sql | 从清洗到入库的链路完整性 |

想加类别：在 `categories` 里加一组关键词，在 `messages` 里加一条对应话术，就完事。

## 写法参考

```
❌ 您好，我是XX，26届本科，熟悉Python、FastAPI、Docker，希望有机会聊聊
   —— 全是标签，没有一件具体的事

❌ 保险条款RAG问答：递归切片、向量+BM25混合检索、阈值拒答，可聊
   —— 信息够了，但「可聊」太轻浮，像约人闲聊

✅ 我之前做过保险条款的RAG问答，从文档切片、向量加BM25混合检索，
   到答不准就拒答，这几块都是我写的。您这岗位也是这个方向吗？
   —— 三个能验证的动作 + 一句具体问话，同行一眼看出不是调包

✅ 我这一年主要做大模型应用落地，RAG问答和Agent调度都做过，
   Python后端也能写。合适的话我把简历发您。
   —— 能力边界说清楚，结尾给动作，HR 不用想怎么回
```

结构：**我做过什么（能验证） + 怎么做的（口语细节） + 一句具体的话头**。
