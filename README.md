# BOSS直聘 手机端自动投递

用一根数据线把安卓手机连上电脑，让脚本在 **BOSS直聘 App 里** 自己翻岗位、读 JD、
判断这个活你干不干得了，再发一句按岗位类别挑好的开场白。

不 root、不 hook、不模拟登录、不改包 —— 就是在真机上模拟点击。

> ⚠️ 先读 [免责声明](#免责声明)。这是一个**给自己用的效率工具**，不是给账号刷量的机器。

---

## 这是什么

- 手机连 USB，ADB + [uiautomator2](https://github.com/openatx/uiautomator2) 驱动真机
- 在「职位」信息流里逐张卡片打开详情，读岗位名 / 公司 / 薪资 / **完整 JD**
- 用你自己的技能清单判断「JD 里有没有我会的技术」，没有就跳过，不打扰对方
- 判断通过 → 点「立即沟通」→ 补一句按类别选好的固定话术（≤80 字，口语化）
- 全过程写台账，可随时 Ctrl+C，重跑从断点继续，**不会重复打扰同一家公司**

## 它不做什么

- ❌ 不抓取、不存储招聘方的任何数据，只在本地记「我投过谁」
- ❌ 不自动回复聊天、不批量骚扰、不群发
- ❌ 不伪造简历、不伪造学历、不冒充他人身份
- ❌ 不绕过平台风控；命中「今日上限 / 操作频繁」立刻停

---

## 为什么是「控制真机」而不是「网页爬虫」

BOSS 直聘的岗位详情、沟通入口、风控都在 App 里。网页版能看到的东西少一半，
而且 DOM 一改就全废。真机方案的好处是：

| | 真机 ADB | 网页 Playwright |
| --- | --- | --- |
| 能看到的数据 | 和用户手点完全一致 | 只有网页版暴露的部分 |
| 沟通入口 | 点「立即沟通」就是真人路径 | 多数接口有签名/风控 |
| 被识别风险 | 低（就是真机在点） | 高（指纹、无头特征） |
| 维护成本 | 界面改版要改选择器 | DOM 改版要重写 |

代价是**必须有手机**，而且速度比接口慢（每投一个 7–15 秒，故意留出人手速的节奏）。

## 四个关键设计

### 1. 学历、经验、薪资一律不筛

招聘软件上的薪资区间和「3-5 年经验」经常是随手写的。设成硬门槛只会漏掉本来能聊的岗位。

列表卡片只判断一件事：**这个岗位还在招吗**（带「停止招聘 / 已关闭」才跳过）。

### 2. 进详情页读完 JD，再判断「我干得了吗」

卡片上没有 JD，所以真正的判断发生在打开详情之后：

```
标题命中 销售/客服/运营/产品经理…        → 跳过
标题是技术岗，但 JD 里没有一个我会的技术   → 跳过（技术栈不对）
标题看不出是什么岗（「线上面试（离职优先）」这类钩子标题）
    ├─ JD 里技术权重够        → 投
    ├─ JD 写了门店/提成/销售指标 → 跳过（其实是销售岗）
    └─ JD 短到没信息可判断     → 投（信息不足不判死）
```

最后一条是踩过坑才加的：BOSS 上大量真实岗位用「线上面试（离职优先）」
「急招！双休」当标题，JD 只有一两句，纯靠技术词匹配会大面积漏投。

判断依据是 `config/profile.yaml` 里的 `skills` —— **只写你真会的**，
写进去了脚本就会替你投你干不了的岗位。

### 3. 话术是固定模板，不按岗位生成

按 JD 关键词把岗位归成 5 类（RAG / Agent / 大模型 / 工程 / 数据），
每类一条**提前写好、人工确认过**的话术，长度 ≤80 字，不替换岗位名。

理由很实际：

- 让模型每次现写，质量会飘，还可能编出你没做过的项目
- 口语化、带一个具体做法，比 300 字自我介绍更容易被回
- 结尾不写「可聊」，技术岗反问一句，通用岗说「合适的话我把简历发您」
- 改文案只改一个 yaml 文件，不用碰代码

### 4. 台账去重 + 断点续跑

每次投递往 `applied.jsonl` 追加一行（公司 + 岗位 + 类别 + 状态 + 时间）。
启动时先读台账，投过的公司直接跳过。所以：

- 中途 Ctrl+C 不会浪费额度
- 第二天重跑不会重复打扰同一家
- 报告直接从台账生成，不用额外统计

## 快速开始

### 0. 你需要

- 一台安卓手机（本脚本在 小米 22011211C / Android 14 / 1440×3200 上标定）
- Windows + Python 3.10+
- 手机和电脑各一根能传数据的 USB 线

### 1. 手机准备

1. 设置 → 关于手机 → 连点「版本号」7 次，打开开发者选项
2. 开发者选项 → 打开 **USB 调试**
3. 小米/红米还要打开 **USB 调试（安全设置）**，否则点击会被系统拦
4. 插线 → 手机弹窗选 **传输文件 / MTP** → 允许 USB 调试（勾「一律允许」）

验证：

```bash
adb devices
# 应该看到  xxxxxxxx   device
```

如果显示 `unauthorized`，看手机屏幕上的授权弹窗；显示空列表就换线/换口。

### 2. 装依赖

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

国内网络建议加清华源：

```bash
.venv\Scripts\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

### 3. 用你自己的简历生成配置

```bash
python scripts/onboard.py --resume 我的简历.pdf --city 北京
```

它会：读简历 → 抽出你会的技术词 → 生成 `config/profile.yaml` →
打印几段可以当话术素材的项目描述。

然后**打开 `config/profile.yaml` 改两处**：

- `skills`：删掉你不会的
- `messages`：把草稿换成你真做过的项目，口语一点（≤80 字）

```bash
python scripts/onboard.py --check     # 校验配置
```

### 4. 体检

```bash
python scripts/doctor.py
```

依次检查：adb 路径 / 设备授权 / App 是否安装 / uiautomator2 能否连上 /
BOSS 是否在前台 / 台账条数 / 今日额度。

### 5. 开跑

```bash
run.bat                    # 跑到今日额度上限
run.bat --limit 20         # 本次最多 20 个
run.bat --dry --limit 10   # 只看判断结果，一条不发（强烈建议先跑这个）
```

全程日志写 `data/auto_YYYYMMDD.log`，跑完自动生成 Markdown 报告。

## 配置说明

`config/profile.yaml`（由 `onboard.py` 生成，已在 `.gitignore` 里）：

| 字段 | 作用 |
| --- | --- |
| `candidate` | 姓名（可空）、城市、备注，只用于报告展示 |
| `skills` | **核心**。`{技术词: 权重}`，权重 3 核心 / 2 熟练 / 1 了解 |
| `categories` | 岗位类别 → 关键词，决定用哪条话术 |
| `messages` | 每类一条固定话术，≤ `fit.max_message_len` 字 |
| `block_titles` | 岗位名命中即跳过（销售/客服/运营…） |
| `block_body` | 标题看不出岗位时，JD 出现这些就跳过（门店/提成/销售指标…） |
| `dev_titles` | 认定「这是技术岗」的特征词 |
| `fit.min_score` | 钩子标题下，JD 技术权重到多少直接投 |
| `fit.short_jd` | JD 短于多少字算「信息不足」→ 放行 |
| `limits.daily` | 每日沟通上限（默认 150） |
| `limits.log_keep_days` | 日志保留天数（默认 1，即只留当天） |
| `limits.log_enabled` | `false` = 完全不写日志文件 |

改完不用重启什么，下次运行自动生效。

## 运行时会发生什么

```
读取台账（已投过的公司 → 跳过）
  ↓
等设备 → 体检 → 数今日已沟通 → 算剩余额度
  ↓
回到「职位」列表
  └─ 逐张卡片：
       打开详情
       ├─ 按钮不是「立即沟通」→ 已联系过，返回
       ├─ fit 判断不通过      → 返回（不打扰对方）
       └─ 通过 → 点「立即沟通」
                 App 自动发默认招呼语（这一步就消耗 1 次额度）
                 输入该类别话术 → 点最右侧发送键
                 校验气泡出现 → 返回列表
                 写台账，随机歇 7–15 秒
```

停止条件：额度用完 / App 提示「上限·频繁」/ 连续 4 次失败 / 列表翻到底。

## 台账与报告

```
data/applied.jsonl     每行一条：{公司, 岗位, 薪资, 类别, 状态, 时间, JD摘要}
data/auto_YYYYMMDD.log 当天完整日志
data/report_*.md       跑完自动生成的报告（类别分布 + 今日明细）
data/quota.json        最近一次额度探测结果
```

**日志只留当天，第二天自动删。** 每次启动时按文件名里的日期清理，
昨天及更早的 `auto_*.log` / `report_*.md` 直接删掉，同一天的报告最多留 5 份。
台账 `applied.jsonl` **永远不会被删** —— 它决定「谁投过了」，删了会重复投递。

嫌占地方可以彻底关掉：`limits.log_enabled: false`，脚本就只在控制台输出，
一个日志文件都不写（台账和报告仍然保留）。

统计累计投递：

```bash
python -c "import json;rs=[json.loads(l) for l in open('data/applied.jsonl',encoding='utf-8')];print(sum(r.get('status')=='ok' for r in rs))"
```

## 已知限制

- **只在一台机器上标定过**：小米 22011211C / Android 14 / 1440×3200。
  `common.tap/swipe` 会按实际分辨率等比缩放，但 **UI 结构变了要改 `selectors`**
  （参考 `references/ui-map.md`，里面记了每个用到的 resource-id 和 Activity）
- **只支持一个账号**，多账号要自己加 profile 隔离
- **发送按钮没有 resource-id**，靠「输入框右侧最右一个可点控件」定位；
  BOSS 改版可能失效，日志里会报 `send_unverified`
- **不处理验证码/滑块**，遇到就停下人工过
- 滑动过快会让 uiautomator2 的 server 掉线，脚本里已做重连，但仍建议别把节奏调太紧

## FAQ

**Q：会不会被封号？**
任何自动化都有风险。这个脚本做了三件降低风险的事：节奏随机 7–15 秒、
命中风控信号立刻停、不重复打扰同一家公司。但**风险仍在，请自己判断是否接受**。

**Q：为什么不自动回复 HR？**
自动回复容易说错话，而且聊天是转化率最高的一环，值得你自己回。
这个工具只负责把「第一句」送到位。

**Q：能不能不用手机，纯接口？**
不建议。接口有签名和风控，且沟通动作没有公开 API，逆向成本远高于维护这套脚本。

**Q：`--dry` 是什么？**
只打开详情读 JD、打印判断结果，**不发任何消息、不消耗额度**。改完配置先跑它。
